# v0.1 Development Chronicle

**Period**: February 22–28, 2026 (7 days, ~20 agent sessions)
**Outcome**: Tag `v0.1` — working 11-profile haptic joystick with MIDI control

## The Arc

### Day 1 — Situation Analysis (Feb 22)

Inherited a codebase with dual-motor support, three PlatformIO environments, and
no hardware validation. Wrote a rework plan proposing custom PID auto-tuning…
then abandoned it in favor of SimpleFOC Studio (the library's own tool). Lesson:
**use existing tools before inventing**.

### Day 2–3 — Motor Won't Move (Feb 23–24)

- Motor calibrated on power-up but ignored position commands
- Suspected PID values, sensor wiring, angle wrapping
- Tried angle_openloop — motor spun but no closed-loop response
- **Root cause**: unknown — same firmware worked the next morning.
  Likely a loose I2C connection to the AS5600 or a partial flash.
  The fix was… turning it off and on again.

### Day 4 — The BOOTSEL Wall (Feb 25–26)

Automated firmware upload via `picotool` requires BOOTSEL mode. Initially worked,
then stopped. Root cause: **USB CDC ringbuffer saturation**.

- RP2040 has a 4 KB CDC buffer
- Telemetry at 10 Hz + statistics + Commander responses ≈ 3 KB/s steady
- Under diagnostic polling: buffer overflows, USB enumeration breaks
- Fix: Added `rb` serial command → writes to RP2040 watchdog scratch register →
  reboots into BOOTSEL without manual button press
- See [../USB_STABILITY_ISSUE.md](../USB_STABILITY_ISSUE.md) for full analysis

### Day 5 — PID Tuning Marathon (Feb 27)

18+ firmware iterations over ~2.5 hours of autonomous agent work:

| Iteration | Change | Result |
|-----------|--------|--------|
| Baseline | P=10, I=0, D=0.5, vel_P=0.125 | 8% tests pass, 9° steady-state error |
| +I term | P=10, I=0.2, D=0.5 | Reduced error to ~3°, introduced oscillation |
| +D term | P=12, I=0.2, D=0.8 | Oscillation damped, 5° error |
| Vel loop | vel_P=0.1, vel_I=0.5 | Smooth approaches, 2° error |
| Final | P=16, I=0.2, D=1.0, lpf_Tf=0.001 | **7/8 quality goals pass** |

Thermal limit is 2.0 V — higher gains cause motor heating on long holds.
See [../tuning/README.md](../tuning/README.md) for methodology.

### Day 5 — Code Pruning

Removed all untested code to establish a proven baseline:
- Dual-motor infrastructure (arrays, conditionals, second motor init)
- `pico_1motor_limited` and `pico_2motor_limited` build environments
- Result: single `pico_1motor_endless` environment, ~1800 lines total

### Day 6 — CI/CD + Merge (Feb 27 afternoon)

- GitHub Actions: build validation + hardware-in-loop tests
- BOOTSEL automated via `rb` command → `picotool load`
- Merged 4 feature branches into dev (modularize-main, trim-wheel, HIL fixes)
- All 6 automated tests passing

### Day 7 — Profiles & Polish (Feb 28)

- Implemented 11 aircraft control profiles (Cessna trim through Airbus sidestick)
- MIDI CC#0 bank select for runtime switching
- Haptic layer v2: per-profile detent maps, soft endstops, rate-limited transitions
- HID: 16-bit axis (0–65535), boot centering, evdev dead zone compensation
- Quality suite: 7/8 pass (Test G Random Walk 18/20 — accepted)

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| SimpleFOC angle mode, not openloop | Closed-loop needed for haptics; openloop has no position feedback |
| Single-motor-only codebase | Multi-motor was untested; YAGNI until proven |
| 2.0 V voltage limit | Thermal: motor gets hot above 2 V on sustained holds |
| Haptic detents via angle offset | Simpler than current-mode torque ripple; works with existing PID |
| MIDI for input, HID for output | Standard protocols; MIDI has bank select for profiles |
| 16-bit HID axis | 10-bit was coarse for ~6500° range; 16-bit gives <0.1° resolution |

## Key Bugs (All Resolved)

| Bug | Fix |
|-----|-----|
| Motor ignores angle commands | Hardware flakiness — power cycle resolved it |
| BOOTSEL mode required manually | Added `rb` serial command → watchdog scratch reboot |
| PID query returns garbage | USB CDC buffer overflow — reduced telemetry rate |
| HID axis stuck at center | Missing `tud_hid_report()` call in main loop |
| Profile switch causes jump | Rate-limited detent transitions (10°/tick max) |
| Endstop overshoot | Soft endstops with configurable margin |
